## 2. Migrations propostas (versionadas no GitHub após autorização)

### Migration A — `0126_a02_recomendacoes_estado.sql`
Nova persistência compartilhada dos estados das recomendações (sem localStorage):

```sql
create table public.a02_recomendacoes (
  id uuid primary key default gen_random_uuid(),
  recomendacao_id text not null,          -- id do motor (ex.: estoque-zerado)
  chave text not null,                    -- ocorrência: ex. "sabor:Coxinha", "conta:ID"
  ocorrencia integer not null default 1,  -- volta do problema gera ocorrência+1
  situacao text not null default 'pendente'
    check (situacao in ('pendente','ciente','adiada','dispensada','resolvida')),
  prioridade text not null check (prioridade in ('baixa','normal','alta','critica')),
  titulo text not null,
  adiada_ate timestamptz,
  ciente_em timestamptz,  ciente_por uuid,
  adiada_em timestamptz,  adiada_por uuid,
  dispensada_em timestamptz, dispensada_por uuid,
  dispensada_motivo text check (char_length(btrim(dispensada_motivo)) between 1 and 500),
  resolvida_em timestamptz, resolvida_por uuid,
  resolvida_dados jsonb,                  -- evidência da resolução (leituras usadas)
  tarefa_id uuid references public.a01_tarefas(id) on delete set null,
  criado_em timestamptz not null default now(),
  atualizado_em timestamptz not null default now(),
  atualizado_por uuid,
  unique (recomendacao_id, chave, ocorrencia)
);

create table public.a02_recomendacoes_historico (
  id bigint generated always as identity primary key,
  estado_id uuid not null references public.a02_recomendacoes(id) on delete restrict,
  ator_id uuid not null, ator_nome text not null,
  acao text not null check (acao in
    ('detectada','ciente','adiada','dispensada','resolvida','reaberta','ocorrencia')),
  detalhe jsonb,                          -- motivo, prazo escolhido, evidência
  ocorrido_em timestamptz not null default now()
);
```
- Histórico: somente INSERT (sem grant de update/delete) e escrita por trigger
  `security definer` — preservado contra alteração indevida.
- RLS: leitura para equipe; escrita apenas `has_role('admin')`.
- Deduplicação de tarefas: índice único parcial em `a01_tarefas`
  `(recomendacao_id, chave) where not concluida and not excluida and
  recomendacao_id is not null` — a segunda inserção simultânea falha no banco
  e a tela informa "já existe tarefa para esta ocorrência".
- Colunas novas em `a01_tarefas`: `recomendacao_id text, rec_chave text,
  rec_ocorrencia integer` (vínculo e dedup).

### Migration B — `0127_a01_tarefas_gestao.sql`
```sql
alter table public.a01_tarefas
  add column excluida boolean not null default false,
  add column excluida_em timestamptz,
  add column excluida_por uuid,
  add column excluida_motivo text
    check (char_length(btrim(excluida_motivo)) between 1 and 500);
-- exclusão lógica sempre completa ou ausente:
--   (excluida ⇒ excluida_em/excluida_por/excluida_motivo preenchidos)
-- GRANT update ampliado: concluida_em, concluida_por (reabrir) e colunas de exclusão
-- CHECK de acao do histórico passa a aceitar: reaberta, excluida, restaurada
-- Trigger preparar_tarefa:
--   • reabertura: concluída → pendente somente admin ou criador; limpa
--     concluida_em/concluida_por; mantém o evento "concluida" no histórico;
--   • excluída não aceita edição; restauração somente admin;
--   • exclusão exige motivo (coluna) e preenche ator/data/hora.
-- Policy de UPDATE: remove "not concluida" do USING (regra passa ao trigger),
--   e impede update de linhas excluídas (exceto restauração admin).
```
Exclusão é **lógica**: nenhuma linha é apagada; sai das listas ativas
(`select * order by concluida` ganha filtro `not excluida` no cliente) e a
Lixeira consulta `excluida = true`. Sem exclusão definitiva pela interface
(nem RLS permite `delete`).

## 3. Comportamento implementado em código (após as migrations)

- **Resolução automática**: a tela compara cada estado ativo com a regra do
  motor nos dados atuais; resolve somente quando a regra **não dispara** e as
  fontes envolvidas estão com **dados suficientes** (falha/sem registros/parcial
  não resolvem; conclusão de tarefa não resolve). Registra evidência, data/hora
  e histórico. Problema que volta gera `ocorrencia+1` vinculada ao histórico.
- **Críticos**: adiamento limitado a 24 h, cartão sinalizado "crítica adiada";
  dispensa de crítico reexpira em 7 dias — enquanto o risco persistir, retorna
  à lista (nada é ocultado indefinidamente).
- **Adiar**: 1 h, 3 h, amanhã, 7 dias ou data/hora personalizados; volta
  automaticamente ao expirar (`adiada_ate`).
- **Ciente**: registra admin/data/hora; situação "ciente" não é resolvida.
- **Dispensar**: exige motivo; registra responsável/data/hora; permanece no
  histórico; reativa se o problema voltar (nova ocorrência).
- **Filtros de situação** (pendentes/cientes/adiadas/com tarefa/resolvidas/
  dispensadas) somados aos filtros de setor e período; situação exibida no
  cartão; lista principal continua por prioridade.
- **Integração recomendação↔tarefa**: sugestão herda título, descrição e
  prioridade; confirmação humana obrigatória; tarefa vinculada e situação
  visíveis no cartão, com atalho para abrir; excluir/concluir tarefa **não**
  dispensa/resolve a recomendação.
- **Dashboard A01**: mesma fonte e regras; resumo da Néia Inteligência respeita
  as situações (ativas = pendentes/cientes/adiadas vencidas); layout A01
  preservado; tarefas sincronizam por realtime já existente.
- **Permissões**: gerência (ciente/adiar/dispensar/restaurar/reabrir) só para
  admin — validado no banco (RLS + trigger), não só na interface; funcionários
  continuam com criar/concluir/editar as próprias, conforme A01.
